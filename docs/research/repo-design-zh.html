一輪研究怎麼跑

每一步只處理一個主要問題。

1

凍結研究題目

代理寫入原始問題、研究類型、交付物、主張範圍和預算。工作流保存契約。後續不得悄悄改題。

輸入：research/contract-input.json　→　輸出：research/contract.json

2

確認文獻與資料

代理取得可核對的來源。它記錄位置、取得狀態、授權、日期和檔案雜湊。缺少來源時，保留缺口。

輸出：題目盤點、文獻紀錄、資料來源紀錄

3

建立主張和研究義務

代理連接主張、證據、分析結果與必要假設。實證研究要檢查識別與推論。理論研究要列出定義與證明義務。

主要紀錄：research/manifest.jsonl

4

分工並產出論文

至少兩名研究代理分工，一名獨立代理審查。實證研究使用核驗的真實資料；模擬資料只用於理論驗證或獨立工程測試。稿件須寫出限制。

交接紀錄：research/team.json　→　審查：research/substantive-review.json

5

執行關卡並修正

工作流檢查整個 package。失敗時，它回傳關卡、原因與 next_tasks。代理修正後再查一次。

候選動作：research/dream-actions.json　→　執行紀錄：research/discovery_tree.jsonl

6

審閱相同版本並交付

審閱者逐頁檢查 PDF。工作流用雜湊綁定審閱、PDF 與編譯輸入。所有必要關卡通過後，才可交付。

輸出：已核對的論文與 replication package，或清楚的阻塞報告

元件各管一件事

研究代理負責判斷。驗證器負責可檢查的條件。

研究工作

代理與 Skill

Skill 指定研究順序。代理找資料、選設計、做分析、寫稿和回應反證。程式不會自行發明文獻、資料或結論。

工具呼叫

MCP

project_status 讀取狀態。audit_package 查關卡。run_workflow 執行完整檢查。run_iteration 執行已宣告的有限動作。

執行與停止

Workflow runner

它檢查凍結契約、記錄 ledger、重跑分析、編譯稿件和合併結果。它用已記錄的執行時間管理預算。

有限試錯

Dream-RSI

它從舊紀錄學習動作順序。它只使用關卡進度當回饋。效果大小、p 值與研究者直覺不進入獎勵。

重要邊界

科學障礙的測試命令成功，只代表命令已執行。若要標記為已解決，還需要具名審閱者、理由與雜湊綁定的證據。

關卡如何作出判定

研究類型不同，必填產物也不同。

層次檢查內容主要檔案
來源題目盤點、文獻、真實資料取得與授權topic · data · literature
論證主張、證據、假設、設計與反證manifest · design · logic
結果數字綁定、乾淨重跑、生成產物一致bindings · replication
交付限制段落、團隊交接、獨立審查、逐頁審閱、發行 PDFcoverage · team · review · latex

complete / 完成

契約、必要關卡、重跑、科學障礙與交付檢查都通過。

blocked / 阻塞

研究義務或必要產物未通過。工作流列出下一項工作。

budget-exhausted / 預算用盡

工作流停止後續階段。它保留已完成的結果與待辦。

interrupted / 動作中斷

Dream-RSI 保留執行中收據。代理先檢查副作用，再決定是否重試。

尚未驗證的目標

目前沒有證據顯示系統能從一句題目穩定產出頂刊論文。下一步需要真實來源、真實資料、完整工作論文、獨立審查和受控比較實驗。

已知工程限制：乾淨重跑使用工作副本，不是作業系統沙箱；Dream-RSI 尚無跨程序鎖；預算記錄是執行秒數，不是 API 金額。詳見實作狀態與研究計劃。

如何執行

下列命令在 repo 根目錄執行。

檢查研究工作流

python3 scripts/run_research_workflow.py \
  --root /path/to/project \
  --contract research/contract-input.json \
  --json

啟動本地 MCP

uv run --no-project --with 'mcp>=2,<3' \
  python scripts/econ_mcp_server.py \
  --root /path/to/project

完整操作順序見工作流指南。工程案例見實驗報告。
